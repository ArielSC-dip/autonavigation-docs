Introducción

Framework de automatización E2E (Playwright). Esta página se genera desde el Knowledge Graph (knowledge/): 117 conceptos, schema v2.

runner.py:main→plugin_registry/plugin_loader→BaseSuite→Suite específica→SafeActions→SmartResolver→BrowserAdapter→motor (playwright)

Instalación

  1. python -m venv .venv (Python ≥ 3.11)
  2. pip install -e .
  3. python -m playwright install chromium
  4. Config central: framework/config/config.global.yaml (systems + runtime). Secretos: copia framework/config/.env.example a .env y rellena (contraseñas como ${VAR}).
Los sistemas son internos: requieren VPN/red local y navegador. No corren en cloud. Detalle: README.md de la raíz.

Conceptos

Glosario derivado de las capas del grafo.

Framework
Cadena de ejecución: runner.py:main → plugin_registry/plugin_loader → BaseSuite → Suite específica → SafeActions → SmartResolver → BrowserAdapter → motor (playwright).
Sistema
Una app web bajo prueba (en plugins/<sistema>/): control_accesos_qa, declaradip_qa, declaradmin_qa, reported_qa, saeradmin_qa.
Suite
Conjunto de pruebas de una sección/feature. Una suite = locators.json + actions.py + suite.py + config.yaml en plugins/<sistema>/<suite>/.
Flow
Escenario E2E reutilizable. Hay 11 flows (ver capa Flows).
Checkpoint
CheckpointManager usa state_file (<workspace>/checkpoints/auth_<user>_<run_id>.json) para guardar el punto del flujo; restore_to_checkpoint re-navega.
Locator
SmartResolver soporta id, placeholder, role(+exact), label, text, alt, title, locator(CSS); UIMap aplica number como nth 1-based y devuelve un ElementRef (native + spec + key), que es la moneda que circula hasta SafeActions.
Action
Interacción atómica de UI en actions.py. actions.py contiene solo interacciones atómicas de UI (click/fill/select/upload).
Strategy
Login del sistema (strategies.py, no editable). Login del sistema via strategies.py (popup <a>, Abrir_Login(), o inline segun el sistema).
Entity
Elemento de UI reutilizable. 14 entities (ver capa Entities).
Pattern
Táctica de automatización reutilizable (ver capa Patterns).

Crear una suite

  1. Esqueleto: tools/new_suite.py --system <s> --suite <n>.
  2. Mapear DOM: main.py --system <s> --suite <n> --users <u> --flows 1.0.
  3. Editar locators.json / actions.py (atómico) / suite.py (orquesta) / config.yaml.
  4. Registrar el concepto suite.<s>.<n> y correr el pipeline del KB.

Reglas obligatorias:

  • rule.actions_only_atomic — actions.py contiene solo interacciones atómicas de UI (click/fill/select/upload).
  • rule.class_naming_for_loader — La clase de actions debe terminar en "Actions" y la de suite en "Suite".
  • rule.deterministic_flows_in_runners — Los runners deben pasar --flows EXPLÍCITO por suite (no depender de last_run).
  • rule.dialog_handler_native — Para diálogos/interrupciones usar watch_for_known_interruptions, no código a medida.
  • rule.isolate_state_file_in_parallel — El aislamiento del state_file en ejecución concurrente lo hace el framework (run_id); NO derives el state_file a mano en código nuevo.
  • rule.locator_number_is_1_based_int — El campo "number" de un locator es nth 1-based y debe ser entero.
  • rule.never_touch_system_strategies_or_config — No modificar strategies.py, config.yaml ni plugin.yaml del SISTEMA (plugins/<sistema>/).
  • rule.no_save_without_confirmation — No pulsar Guardar/Enviar sin confirmar que la sección DEBE persistir (registrar GUARDA/NO GUARDA).
  • rule.orchestration_in_suite — suite.py orquesta orden, condicionales, verificación, checkpoints e interpretación.
  • rule.use_safe_actions — Usar los verbos de SafeActions (no la API cruda del motor desde la suite).

Ejecutar

  1. main.py --system <s> --suite <n> --users <u> --flows 1.0-2.0 (usa rangos de flows EXPLÍCITOS).
  2. Artefactos en plugins/<s>/<n>/artifacts/run_<id>/ (video si record_video: true).
  3. Varias suites de Reported: tools/run_reported.py (secuencial).
